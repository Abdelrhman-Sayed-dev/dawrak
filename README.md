# دورك (DAWRAK) — نظام حجز دور العيادات

FastAPI + PostgreSQL، والواجهة ملف واحد `index.html` يقدّمه نفس السيرفر.

## روابط الدخول (بوابة منفصلة لكل دور)
| الدور | صفحة الدخول | بعد الدخول | تسجيل جديد |
|---|---|---|---|
| المريض | `/patient/login` | `/patient/dashboard` | `/patient/register` |
| الطبيب | `/doctor/login` | `/doctor/dashboard` | لا يوجد (يضيفه المدير) |
| المدير | `/admin/login` | `/admin/dashboard` | لا يوجد (إنشاء من السيرفر فقط) |

الـ API: `POST /api/patient/login` و`/api/doctor/login` و`/api/admin/login` (الدور يحدده المسار، لا ما يرسله العميل). تم حذف `/api/login` القديم.

## تشغيل محلي
```
pip install -r requirements.txt
export DATABASE_URL="postgresql://..."
export JWT_SECRET="نص-عشوائي-طويل"       # لو تُرك فارغاً يُولَّد سر مؤقت (تنتهي الجلسات عند إعادة التشغيل)
psql -d clinic_queue -f database.sql
python create_admin.py <username>        # ينشئ المدير ويطلب كلمة المرور (12+ حرفاً)
python main.py                           # http://localhost:3000
```

## الحسابات
- **المدير**: `python create_admin.py <username>` فقط. لا يوجد تسجيل عام ولا كلمة مرور في الكود أو في `database.sql`.
- **الأطباء**: من لوحة المدير (اسم مستخدم فريد وكلمة مرور مشفّرة bcrypt لكل طبيب).
- **المرضى**: يسجّلون بأنفسهم.

## متغيرات البيئة
| الاسم | الوصف |
|---|---|
| `DATABASE_URL` | رابط PostgreSQL (لـ Neon: بدون `&channel_binding=require`) |
| `JWT_SECRET` | سر توقيع التوكن (إجباري في الإنتاج؛ Render يولّده) |
| `GOOGLE_CLIENT_ID` | اختياري، لتسجيل الدخول بجوجل (للمرضى فقط). لو تُرك فارغاً يختفي زر جوجل |

## فحص سريع للصلاحيات (بعد التشغيل)
```
curl -i localhost:3000/api/admin/doctors                       # 401 بدون توكن
curl -i -XPOST localhost:3000/api/admin/login -H 'content-type: application/json' -d '{"username":"x","password":"y"}'   # 401
# توكن طبيب على /api/admin/doctors => 401 ، توكن مريض على /api/doctor/queue => 401
```

## تسجيل الدخول بجوجل (للمرضى فقط)
1. Google Cloud Console ← Google Auth Platform ← Clients ← Create client ← **Web application**.
2. في **Authorized JavaScript origins** أضف `http://localhost:3000` ورابط الموقع (مثل `https://dawrak.onrender.com`) بدون `/` في آخره. اترك Redirect URIs فارغاً.
3. انسخ الـ Client ID وضعه في المتغير `GOOGLE_CLIENT_ID` (لا حاجة لـ Client Secret).
4. من **Audience**: اضغط Publish app (أو أضف Test users أثناء التجربة).
5. المكتبات `google-auth` و`requests` موجودة في `requirements.txt`.

ملاحظات أمان:
- المريض الجديد بجوجل يكمل بياناته (هاتف/عمر...) ثم يُنشأ حسابه، وكلمة مروره عشوائية (يدخل بجوجل فقط).
- التسجيل اليدوي لا يقبل إيميلاً كاسم مستخدم (حروف/أرقام/_/. فقط)، حتى لا يستطيع أحد حجز إيميل غيره والاستيلاء على حسابه عند دخوله بجوجل.

## جدول العيادة والحجز الإلكتروني
- المدير يحدد لكل طبيب (عند الإضافة أو التعديل): أيام العمل، بداية ونهاية الكشف، مواعيد فتح وإغلاق الحجز الإلكتروني (إغلاق فارغ = حتى نهاية الكشف)، وحداً أقصى يومياً (اختياري).
- الحجز الأونلاين يفتح ويُغلق تلقائياً حسب الجدول (بتوقيت القاهرة): يوم عمل + داخل نافذة الحجز + لم يكتمل الحد الأقصى. المريض يرى سبب الإغلاق («يفتح الحجز الساعة ...»، «العيادة لا تعمل اليوم»، «اكتمل العدد»).
- موظف الاستقبال في تابة **الحجز** يتدخل للاستثناءات فقط: «فتح الحجز استثناءً» أو «إغلاق الحجز استثناءً» لليوم الحالي، و«العودة لجدول العيادة». الاستثناء يسري اليوم فقط ويُلغى تلقائياً غداً، ويُسجَّل في سجل العمليات. الاستثناء بالفتح يتجاوز الحد الأقصى أيضاً.
- الحد الأقصى يحسب الحجوزات غير الملغاة لليوم ويمنع الحجز الأونلاين فقط؛ تسجيل الحضور المباشر من الاستقبال متاح دائماً.
- طبيب بلا أيام عمل محددة (الأطباء القدامى) يبقى على النظام اليدوي: الموظف يضغط «بدء الحجز لليوم» ويُغلق تلقائياً مع اليوم التالي.
- لقاعدة موجودة شغّل `migration_schedule.sql` (أو اتركه للسيرفر فيضيف الأعمدة تلقائياً).

## الحجز المجاني لكل الأطباء (من لوحة المدير)
- في «نظرة عامة» كارت «الحجز المجاني لكل الأطباء»: زر «تفعيل» يفتح نافذة لاختيار المدة (يوم / أسبوع / شهر / ٣ شهور أو عدد أيام مخصص حتى 365) وتبدأ من اليوم (1 = اليوم فقط).
- خلال المدة تصبح رسوم الحجز الإلكتروني صفراً عند كل الأطباء تلقائياً (ويظهر للمريض السعر القديم مشطوباً مع «مجاناً»)، وتعود رسوم كل طبيب بعد انتهاء المدة بدون أي إجراء. سعر الكشف لا يتأثر، ورسوم كل طبيب المحفوظة لا تتغير.
- «تغيير المدة» يستبدل المدة الحالية بمدة جديدة من اليوم، و«إنهاء الآن» يوقفه فوراً. الجدول `free_booking` (صف واحد) ويُنشأ تلقائياً أو من `migration_schedule.sql`.

## تطبيق PWA وإشعارات الموبايل (Web Push)
التطبيق يُثبَّت على الشاشة الرئيسية من Chrome ويفتح في نافذة مستقلة بأيقونة دورك، ويستقبل إشعارات حقيقية من السيرفر حتى والتطبيق مغلق.

### الملفات
| الملف | الوظيفة |
|---|---|
| `static/manifest.webmanifest` | بيانات التطبيق (الاسم، الأيقونات، `standalone`، RTL، اختصارات «الأطباء» و«حجزي») |
| `static/sw.js` | Service Worker واحد للنطاق `/`: التثبيت + استقبال push + صفحة «لا يوجد اتصال». لا يخزّن أي API أو بيانات |
| `static/icons/*` | أيقونات من شعار دورك (192/512، maskable، Apple 180، badge للإشعار) |
| `webpush.py` | تشفير aes128gcm (RFC 8291) + VAPID (RFC 8292) + الإرسال، بدون مكتبات خارجية غير `cryptography` |
| `push.py` | منطق الأحداث ومن يستقبل ماذا ومنع التكرار |
| `generate_vapid.py` | توليد مفاتيح VAPID (مرة واحدة) |
| `migration_push.sql` | جداول الإشعارات لقاعدة موجودة (السيرفر ينشئها تلقائياً أيضاً) |

**مهم:** أضف مجلد `static/` وملفات `webpush.py` و`push.py` إلى المستودع مع `main.py` و`index.html`، وإلا لن ينشر Render الأيقونات والـ Service Worker.

### التفعيل (مرة واحدة)
1. `python generate_vapid.py` ← ضع `VAPID_PRIVATE_KEY` و`VAPID_SUBJECT` (بريدك بصيغة `mailto:...`) في متغيرات البيئة على Render. بدونهما يعمل التثبيت لكن زر الإشعارات يظهر «غير متاحة» ولا يتأثر أي شيء آخر.
2. الإشعارات تتطلب HTTPS (Render يوفره). لا تغيّر `VAPID_PRIVATE_KEY` لاحقاً لأن ذلك يُبطل اشتراكات الأجهزة الحالية (تعيد الاشتراك تلقائياً عند فتح التطبيق).
3. (اختياري، لتذكير الأدوية كإشعار) أنشئ مهمة في cron-job.org كل دقيقة على `https://موقعك/api/push/cron` مع Header باسم `X-Cron-Key` وقيمته `CRON_SECRET`. هذا يبقي خدمة Render المجانية صاحية أيضاً. بدونه تبقى إشعارات الإشعارات الأخرى تعمل (لأنها تُرسل لحظة حدوث الحدث)، وتذكير الدواء يبقى داخل التطبيق كما كان.

### من يستلم ماذا
| المستلم | الحدث |
|---|---|
| المريض (حساب أو ضيف) | تأكيد الحجز · اقتراب الدور (أمامك ≤ `PUSH_NEAR_AHEAD`، الافتراضي 2) · «أنت التالي» · بدء دورك · إلغاء العيادة لحجزه |
| المريض (حساب فقط) | صدور الروشتة (أول حفظ للتقرير فقط) · موعد الدواء (مع cron) |
| الطبيب | حجز جديد · تسجيل حضور مباشر · إلغاء/تأجيل المريض · بدء كشف مريض |
| موظف الاستقبال | حجز أونلاين جديد · إلغاء/تأجيل المريض |

كل إشعار «اقتراب/التالي» يُرسل مرة واحدة لكل حجز، ويُسمح بتنبيه ثانٍ لو رجع المريض للخلف (تأجيل/نقل) ثم اقترب ثانية. الضيف (بلا حساب) يفعّل الإشعارات من نافذة تأكيد الحجز أو صفحة «حجزي»، ويرتبط الجهاز بحجوزاته النشطة فقط بعد التحقق من رقم الهاتف. عند الخروج من أي حساب يتخلى الجهاز عن اشتراكه حتى لا تصل إشعارات مستخدم سابق لمن يستعمل الجهاز بعده.

متغيرات اختيارية: `PUSH_NEAR_AHEAD` (1–10) · `PUSH_SYNC=1` (لبيئات Serverless مثل Vercel حيث تُقتل المهام بعد الرد؛ على Render لا حاجة) · `PUSH_ALLOWED_HOSTS` (مضيفو خدمات دفع إضافيون؛ الافتراضي Google/Firefox/Apple/Windows فقط).

### التثبيت على الأجهزة
- **أندرويد + Chrome:** يظهر بانر «ثبّت دورك» (أو من قائمة ⋮ ← تثبيت التطبيق)، ويظهر جرس الإشعارات في الهيدر.
- **iPhone:** الإشعارات تعمل فقط بعد التثبيت من **Safari** (مشاركة ← إضافة إلى الشاشة الرئيسية) وفتح التطبيق من الشاشة الرئيسية، ويلزم iOS 16.4 أو أحدث. الواجهة تشرح الخطوات تلقائياً.
